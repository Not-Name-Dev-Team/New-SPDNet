# 服务端 Web 前端 —— 可读性、排版与规模问题处理记录

范围：`server/web/src` 全部 12 个视图 + 5 个组件 + `style.css` 设计系统。
所有对比度为按 WCAG 相对亮度公式**实测**的数值，非估测。全部改动已通过 `npm run build` 并在产物中逐条核对。

---

## 一、后台管理：随数据量恶化的三个问题

后台是唯一**会随用户数增长而持续劣化**的页面，性质比纯样式问题严重，优先处理。

### 1.1 分配前缀的「选择玩家」下拉（功能已不可用）

**症状**：上千用户时，`PlayerPrefix.vue` 的「选择玩家」下拉只能选到当前页的 20 个人，
换页又是另一批，搜索也搜不全 —— 前缀管理基本无法使用。

**根因有两层**：

1. 该下拉用 `v-for="player in players"` 渲染 `el-option`，无分页、无懒加载。
2. 更关键的是 `players` 数据源已被破坏：`Admin.vue` 主表改为服务端分页后，
   `players` **只等于当前页的 20 条**，却被整个传给了下拉组件。
   这是"修了主表分页、没同步另一个消费者"造成的回归。

**处置**：下拉改为服务端远程搜索（`remote` + `remote-method` + 300ms 防抖），
按关键词调 `adminApi.getPlayers(0, 20, null, keyword)`。
后端 `AdminController` 已有 `search` 参数与 `findByNameContainingIgnoreCase`，**无需改后端**。
`Admin.vue` 不再向该组件传 `players`。

### 1.2 页面过长

四个区块（玩家管理 / 广播 / 系统信息 / 前缀管理）原先在同一条纵向流里堆叠。
前缀管理区块自身会随前缀数量持续增行，叠加前三块后整页极长。

**处置**：改为 `el-tabs`，一次只渲染一块。

### 1.3 角色筛选「玩家」必然失败（独立发现的功能故障）

- 前端下拉写 `value="PLAYER"`。
- 后端 `UserRole` 枚举常量实际是 **`USER`**（`UserRole.java`：`USER("玩家")`, `ADMIN("管理员")`, `BANNED("封禁")`）。
- `UserRole.valueOf("PLAYER")` 抛 `IllegalArgumentException` → 表格清空 + 弹「加载数据失败」。
  **必然复现**，与数据量无关。选「管理员」「已封禁」正常。

**同一处第二个 Bug**：`AdminController` 返回 `player.getRole().name()`（英文枚举 `USER`/`ADMIN`/`BANNED`），
而 `format.js` 的映射表里只有 `'PLAYER'`、没有 `'USER'`，
于是 `displays[role] || role` 把 **`USER` 原样显示**在角色列。

**处置**（不动数据库，风险最低）：`Admin.vue` 的筛选项 `PLAYER` → `USER`；
`format.js` 补 `'USER'` 映射，并**保留** `'PLAYER'` 键兼容旧数据。

> 前后端对角色枚举名共有三套写法（`USER` / `PLAYER` / `玩家`），
> 且 `format.js` 同时兼容中英文两套 —— 说明这是一次已经发生过的语义漂移的重演。
> 后续新增角色时，三个映射点需同步：`UserRole`、`Admin.vue` 筛选项、`format.js`。

### 1.4 主表：横向滚动死区

表格各列固定宽合计约 870px，而 `overflow-x:auto` 只写在 768px 以下。
**769–1000px 区间**表格溢出，却被容器的 `overflow:hidden` 静默裁掉 ——
「操作」列（封禁/删除）完全点不到。已把滚动断点提前到 1000px 并给表格兜底最小宽度。

## 二、根因 A：`--text-tertiary` 对比度不达标

`style.css` 原定义 `--text-tertiary: #71717a`。实测（括号内为最差背景 `#1a1a24` 卡片底色）：

| token | 原值 | 卡片上 | 页面底色上 | 判定 |
|---|---|---|---|---|
| `--text-secondary` | `#a1a1aa` | 6.73:1 | 7.71:1 | AA 通过 |
| `--text-tertiary` | `#71717a` | **3.57:1** | 4.09:1 | **不达 AA 正文 4.5:1** |
| `--text-muted` | `#52525b` | 2.23:1 | 2.56:1 | 仅装饰 |

`--text-tertiary` 被用在 **40 余处渲染真实内容**（标签、时间、说明、词条名）。

**处置**：直接抬升该 token 到 `#8b8b96`（卡片上 **5.12:1**，AA 通过），
保留其"比 secondary 弱"的层次语义。
逐处替换易漏且会不断回流，改 token 是唯一能一次性收口的方式。

同时把若干**关键内容**从 tertiary 提升到 secondary（更强一档，而非仅到达标线）：
三个大数字的唯一区分标签（每日挑战）、时间戳（聊天/战绩）、
图鉴词条名与「使用 N 次」数据（玩家页）、空状态与分隔文案（认证页）、管理员要照念的玩家 ID。

**明确保留 tertiary/muted 的场合**：装饰性图标（`expand-icon`、
输入框图标）、禁用态按钮、以及奖牌渐变里的 `#71717a`（那是背景色，不是文字）。

## 三、根因 B：手工维护的固定栅格在断点处失配

排行榜与每日挑战的记录表都用「手写固定 px 轨道 + 各断点改轨道数」，
同时又用隐藏列做响应式 —— **两套机制并行**，导致轨道数与可见子元素数对不上，
溢出后又被容器的 `overflow:hidden` 裁掉（同样是静默失败）。

**处置**：改为**弹性轨道**（`minmax`），数值列按内容自适应、名称列占剩余空间，
**断点只负责 `display:none` 整列**，不再手工数轨道。
容器由 `overflow:hidden` 改为横向可滚动。

> 若日后仍需手写固定轨道，必须同步维护各断点隐藏的列，否则必然错位。

## 四、其余已修项

**聊天页**
- 高度计算**减了两次** `--header-height`（`.app-main` 已用 padding-top 让出头部高度），
  还多减了一个没有对应元素的 `200px` → 页面必然出现永久滚动条。已改为只减自身 padding。
- 角色标签直接渲染 `user.role`，会泄露英文枚举 → 改用 `getRoleDisplay`。
- 900px 以下侧栏 `display:none`，在线名单在手机端彻底消失 → 改为可点击折叠。
- 消息时间、空状态文案由 tertiary 改 secondary；用户名的省略号补 `title`。

**认证页（登录/注册/重置）**
- Element Plus 的校验错误是 `position:absolute; top:100%`，不占文档流，
  而 `.auth-form` 只有 12px 间距 → **错误文案压住下一个字段**。已为每个字段留出提示高度。
- `min-height:100vh` 在 `.app-main` 内会溢出可视区，卡片**永远无法垂直居中** → 减去头部高度。
- 密码上限登录页写 20、另两页写 32，而后端 `PlayerController` 强制 **6–32** →
  **21–32 位密码能设置却无法登录**。统一为 32。
- 验证码输入 `flex:1` 缺 `min-width:0`，会把"发送验证码"按钮挤出容器。
- 产品说明、分隔文案改 secondary。

**玩家页**
- 删除一整块死 CSS（`.rank-info`/`.rank-display`/`.rank-label`/`.rank-progress`/`.progress-*`）
  及配套的 `progressPercent`、`rankDiff`（模板零引用）。
  其中重复定义的 `.rank-number{font-size:3rem}` 因同特异性靠后，**实际覆盖了真正生效的规则**。
- 删除 `.game-stats` 上的 `grid-template-columns`（该元素是 `display:flex`，规则恒无效）。
- 图鉴词条名、`item-meta` 由 tertiary + 11px 提升为 secondary + 12px。

**其他**
- `Profile.vue` `.user-badges` 补 `flex-wrap`（含"注册于…"长标签，窄屏会顶破容器）。
- `PrefixDetail.vue` 的硬编码紫统一到 `--gradient-primary`。
- `Admin.vue` 的 `headerStyle()` JS 对象（硬编码 `#a78bfa` 等非调色板色，
  会盖掉设计系统自己的 `.el-table th` 规则）改为 scoped CSS + token。
- `DailyChallenge.vue` 的 `#ef4444` 比色统一到 `--accent-rose`；
  删掉对中文表头恒为空操作的 `text-transform: uppercase`。
- 删除死代码 `adminApi.getAllPlayers()` / `playerApi.getAllPlayers()`
  —— 前者是 `size:1000` 全量拉取的入口，留着会被误用（本次下拉故障即源于此）。
- 排行榜、统计数字加 `font-variant-numeric: tabular-nums`，
  避免比例数字在刷新/轮询时逐行抖动。

## 五、明确**不是**问题的地方（避免误改）

- **后台主表本身不是"页面大"的元凶**：它已是服务端分页（每页 20 条）。
  不要为"变小"去改它的分页或加虚拟滚动 —— 问题在下拉与单页堆叠。
- 三个认证页的卡片几何、字段间距、按钮宽度、断点几乎逐字节相同；
  感知到的"不一致"来自内容层（登录页的"忘记密码"是纯文字链、注册页独有验证码行），
  **不是间距不一致**，不要为此改布局。
- `Chat.vue` 长消息已正确 `word-break: break-word`，并已设 `min-height:0` 规避 flex 滚动陷阱。
- `Player.vue` 数值单元格用 `monospace` 对齐，是值得推广的正面样板。
- 各视图 scoped 块中同名的 `@keyframes` 因 scoped 隔离**不会冲突**。
- `white` 与 `#fff` 混用在此背景上视觉无差别。
- 装饰性图标的原始 `px` 尺寸属合理用法（只有 11px **正文**才是缺陷）。
